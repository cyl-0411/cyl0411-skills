# QEC 论文阅读输出模板

按下面骨架生成最终 Markdown。根据论文内容增删句子，但保留整体结构和末尾表格。

```md
# <论文标题>

## 0. 摘要概述
- 用 3-6 句概括论文要解决的问题。
- 用 1-2 句概括核心方法或系统设计。
- 用 1-2 句概括最重要的实验结果或硬件指标。
- 最后用 1 句总结论文意义或适用场景。

## 1. 研究背景与动机
- 论文试图解决什么问题。
- 为什么现有方法不足。
- 目标码族、应用场景或硬件场景是什么。

## 2. 核心创新点
- 创新点 1：<算法/结构/系统上的新意>
- 创新点 2：<与现有工作的关键差别>
- 创新点 3：<若有硬件-算法协同或噪声模型贡献，单列说明>

## 3. 具体实现方法与架构
- 算法框架：<解码器类型、模型结构、数据流、关键模块>
- 复杂度：<时间复杂度、空间复杂度，或经验扩展趋势>
- 硬件实现：<FPGA/ASIC/CPU/GPU/TPU，器件或工艺节点，主要资源>
- 存储与数据通路：<SRAM/BRAM/LUT/寄存器/参数量等>

## 4. 详细性能评估
- LER：<指标数值 + 条件，如 d、p、轮数、噪声模型>
- 基线比较：<相对 MWPM、UF、PyMatching、其他硬件/算法的提升>
- 延迟 / 吞吐：<每轮时间、端到端延迟、吞吐率>
- 功耗 / 面积 / 频率：<如果论文给出>

## 5. 噪声模型与实验设置
- 噪声模型名称：<phenomenological / circuit-level / SI1000 / biased ...>
- 构建方式：<覆盖哪些门、测量、重置、相关错误>
- 参数范围：<p 的范围、轮数、码距范围>
- 与真实硬件或目标应用的关系：<若论文说明>

## 6. 优势、局限与适用边界
- 优势：<准确率、速度、硬件友好、低功耗、可扩展性、泛化性等>
- 局限：<只在小码距验证、未给实测功耗、只支持某噪声模型等>
- 适用边界：<适用于何种码族/噪声/硬件条件>

## 7. 论文指标表

| Implementation | Algorithm | Distance | Weight Type | Memory | LER | Decode time | Frequency | Power | Temperature | Noise Model |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| <平台/工艺> | <算法名> | <d 或 L> | <权重类型> | <资源/存储> | <LER + 条件> | <每轮或每次解码时间> | <时钟> | <功耗/能耗> | <工作温度> | <噪声模型> |
```

如果论文有多组实现配置，例如 `phenomenological` 和 `circuit-level` 两种结果，就在表格里写多行。

写表格时优先把“数字 + 条件”放在同一格里，例如：`d=11, p=5e-4, circuit-level noise 下 LER 比 Clique 低 6 个数量级`。

`Weight Type` 不要空着。若原文明确说支持 weighted edges，就写 `Arbitrary`；否则直接写 `N/M`。
